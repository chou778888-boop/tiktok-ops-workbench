# 产品—链接利润分析模型重构设计

## 1. 设计目的

将当前“链接利润日报”从一张近 7 天横向录入表，重构为适合多店、多链接、同品运营的两级利润工作台：

1. 产品整体：汇总同一产品在全部店铺链接中的销量、销售额和贡献利润，并比较各链接表现。
2. 单条链接：填写链接下全部 SKU 的当日售价与销量，查看 SKU 商品毛利润、链接贡献利润，并追踪指定 SKU 的 7 天调价观察。

原《利润 new.xlsx》继续作为计算口径和业务字段参考，但不复制其把每日录入、成本配置、历史和计算结果堆在一张表中的排版。

本轮仍使用演示数据验证信息架构和交互，不导入 Excel，不写入正式团队经营数据。领域模型、状态机和数据接口必须按可持久化标准设计，后续接入团队云端时不推翻本轮代码。

## 2. 设计原则

- 产品整体与单条链接是团队可见的两个核心分析维度。
- 店铺是链接属性和筛选条件，不再形成第三套独立利润页面。
- 日常录入只保留高频输入；低频档案、自动计算和历史分析分区管理。
- 指标名称必须匹配计算边界；成本覆盖不完整时不使用“净利润”。
- 计划性调价与经营异常分开处理，观察期内不提前下结论。
- 链接、SKU、成本、佣金和调价记录均保留历史，不做硬删除。
- 页面强调行动和填写效率，不以展示更多字段为目标。

## 3. 指标分层与正式命名

### 3.1 SKU 商品毛利润

在当前可获得字段下：

```text
SKU 销售额 = 当日实际售价 × 当日销量
SKU 单件商品毛利润 = 当日实际售价 × (1 - 有效佣金率) - 有效单件成本
SKU 商品毛利润 = SKU 单件商品毛利润 × 当日销量
```

“有效单件成本”和“有效佣金率”使用当日生效版本，并在日报保存时形成快照。以后修改成本档案不得改变历史计算结果。

当后续补齐平台费、履约、退款和优惠字段时，SKU 毛利润模型扩展为贡献利润分层，但不修改每日记录的主键和历史快照结构。

### 3.2 链接贡献利润

```text
链接商品毛利润 = 链接下全部启用 SKU 商品毛利润之和
链接贡献利润 = 链接商品毛利润 - 寄样金额 - 广告营销费 - 其他链接级调整费用
链接贡献利润率 = 链接贡献利润 ÷ 链接销售额
```

页面统一使用“链接贡献利润”。只有当商品、平台、履约、退款、广告及其他必要变动成本全部覆盖后，才允许升级名称。

### 3.3 产品整体指标

产品整体汇总选定日期或区间内所有纳入统计的链接：

- 产品总销量
- 产品总销售额
- 产品链接贡献利润合计
- 综合贡献利润率
- 有效链接数、新上线数、已下架数
- 调价观察中链接数

已下架链接在下架日期之后不进入当日汇总，但保留历史区间数据。

## 4. 领域模型

### 4.1 产品 `Product`

- `id`：内部不可变 ID
- `code`：团队产品简称，例如 JZZ
- `name`：正式名称
- `category`
- `status`：active / archived
- `createdAt`、`updatedAt`

### 4.2 公共 SKU `SkuMaster`

- `id`
- `productId`
- `code`
- `name`
- `specification`
- `standardCost`
- `currency`
- `status`：active / inactive
- `effectiveVersions`：标准成本版本记录

公共 SKU 不保存店铺售价。

### 4.3 店铺商品链接 `Listing`

- `id`：内部不可变 ID，URL 不作为主键
- `productId`
- `storeId`
- `platformListingId`
- `url`
- `displayName`
- `ownerId`
- `currency`
- `timezone`
- `predecessorListingId`：新链接承接旧链接时使用
- `lifecycleStatus`
- `launchedAt`、`delistedAt`
- `urlVersions`

生命周期状态只包含：draft、active、paused、delisted、archived。

### 4.4 链接 SKU `ListingSku`

表示某个公共 SKU 在某条链接中的独立经营报价：

- `id`
- `listingId`
- `skuId`
- `active`
- `storeCostOverride`
- `commissionRateOverride`
- `effectiveVersions`
- `activatedAt`、`deactivatedAt`

同一公共 SKU 在不同链接中的售价、佣金和特殊成本互不影响。

### 4.5 SKU 每日经营记录 `ListingSkuDailyFact`

- `id`
- `listingId`
- `listingSkuId`
- `dateKey`
- `price`
- `units`
- `revenue`
- `unitGrossProfit`
- `skuGrossProfit`
- `costSnapshot`
- `commissionSnapshot`
- `entryStatus`
- `enteredBy`、`enteredAt`
- `updatedBy`、`updatedAt`

唯一约束：`listingSkuId + dateKey`。

`units = 0` 与 `units = null` 含义不同：前者代表已确认无销量，后者代表尚未填写。

### 4.6 链接每日费用 `ListingDailyExpense`

- `listingId`
- `dateKey`
- `sampleQuantities`
- `sampleCostSnapshot`
- `marketingSpend`
- `adjustments`
- `entryStatus`
- 审计字段

唯一约束：`listingId + dateKey`。

### 4.7 调价观察 `PriceObservation`

- `id`
- `productId`
- `listingId`
- `listingSkuId`
- `oldPrice`
- `newPrice`
- `purpose`：本期固定为目标 SKU 动销
- `startedAt`
- `baselineStart`、`baselineEnd`
- `observationStart`、`observationEnd`
- `status`
- `baselineSnapshot`
- `resultSnapshot`
- `decision`
- `createdBy`、`completedBy`

同一 `listingSkuId` 同一时间最多存在一个进行中的观察。

## 5. 三套独立状态机

### 5.1 链接生命周期

```text
准备上线 → 正常运营 ↔ 暂停运营 → 已下架 → 已归档
```

“调价观察中”不属于链接生命周期。

### 5.2 每日填写状态

```text
待填写 → 填写中 → 已完成 → 已修改
                    ↘ 已补录
```

完成后再次修改必须记录修改人和时间。

### 5.3 调价观察状态

```text
观察中（第 1–7 天）→ 待复盘 → 已确认结果 → 已结束
```

结果标签独立保存：动销改善、动销无明显改善、动销达成但利润承压、调价未达预期、数据不足。

## 6. 产品整体页

### 6.1 页面任务

让主管或运营先确认某个产品在所有店铺链接中的整体经营情况，再进入需要填写或调整的具体链接。

### 6.2 顶部控制

- 产品选择
- 日期或区间
- 状态筛选：有效、新上线、观察中、已下架
- “新增链接”与“产品 / SKU 设置”进入次级抽屉

### 6.3 产品整体汇总

首要展示产品总销量、总销售额、链接贡献利润合计和综合贡献利润率。链接状态数量采用紧凑辅助信息，不重复做大卡片。

### 6.4 链接比较表

每条链接一行：

- 店铺与链接简称
- 生命周期状态
- 今日填写状态
- 今日销量
- 近 7 天日均销量及变化
- 销售额
- 链接贡献利润
- 贡献利润率
- 调价观察进度

点击行进入单条链接；“待填写”链接可直接从行内进入今日填写。

产品整体销量用于识别链接间分流：目标链接增长但产品整体不增长时，系统标记“可能为链接间转移”，不视为明确新增。

## 7. 单条链接页

### 7.1 链接上下文

固定显示产品、店铺、链接简称、平台链接、生命周期状态、负责人和经营日期。

### 7.2 链接汇总

紧凑展示：今日销量、销售额、SKU 商品毛利润、寄样与营销、链接贡献利润、贡献利润率。贡献利润是主指标，销量是动销判断主指标。

### 7.3 今日 SKU 快捷填写表

每个 SKU 一行，只保留：

- SKU 名称 / 规格
- 今日售价（可编辑）
- 今日销量（可编辑）
- 单件商品毛利润（自动）
- SKU 商品毛利润（自动）
- 近 7 天变化摘要
- 填写或观察状态

交互规则：

- 默认带出前一天售价，但不自动带出销量。
- Tab / Enter 顺序移动到下一输入框。
- 页面持续显示已填写数量，例如 8/10。
- 未填写、已确认 0 销量和已填写非零销量使用不同状态。
- 可主动将剩余未填销量确认成 0，但必须二次确认。
- 正在调价观察的 SKU 置顶，其他 SKU 保持稳定排序。
- 一次提交整条链接当天数据，校验信息就地显示，不逐字段弹窗。

### 7.4 近 7 天详情

默认不使用全量横向 7 天矩阵。每行只显示售价、销量和 SKU 毛利润变化摘要；点击 SKU 行后在行下展开 7 天明细：日期、售价、销量、单件商品毛利润、SKU 商品毛利润。

### 7.5 链接级费用

SKU 表下方统一填写各寄样类型数量、广告营销费和其他调整费用。寄样金额由有效寄样成本版本自动计算。

费用不随意分摊到 SKU。SKU 层展示商品毛利润，链接层展示贡献利润。

## 8. 7 天调价观察

### 8.1 创建

当某 SKU 售价改变时，页面询问是否创建计划性调价观察。价格纠错可以跳过观察。创建时自动记录原价、新价、目标 SKU、操作人和前 7 个完整自然日基线。

### 8.2 观察期

- 固定 7 个完整自然日。
- 第 1–6 天只展示趋势，不提前判定。
- 数据缺失时显示完成度，不补造 0。
- 观察期间仍持续显示止损信息，例如单件商品毛利润为负或链接贡献利润转负；计划性调整只抑制普通价格异常提示，不抑制利润风险。

### 8.3 指标优先级

1. 主要指标：目标 SKU 调整后 7 天日均销量相对前 7 天变化。
2. 产品保护指标：同产品全部链接总销量是否增长，用于识别链接间转移。
3. 利润保护指标：目标 SKU 商品毛利润和链接贡献利润是否转负或明显承压。
4. 诊断指标：销售额变化。

初期将目标 SKU 日均销量提升 10% 作为临时参考线，必须以配置形式实现。累积足够历史后，可根据 SKU 自身波动范围调整阈值。

### 8.4 结果

- 动销改善：目标 SKU 动销明显提高，产品整体未显示完全分流。
- 动销无明显改善：目标 SKU 变化未超过参考线。
- 动销达成但利润承压：动销提高，但 SKU 或链接贡献利润转负或明显下降。
- 调价未达预期：动销没有改善且利润下降。
- 数据不足：观察期日报不完整、库存异常或有效天数不足。

系统只给出保持、继续观察或复盘价格的建议，不自动修改售价。

## 9. 数据流与计算边界

```text
产品 / SKU / 链接档案
        ↓ 读取当日有效版本
每日售价与销量 + 链接费用
        ↓ 纯计算函数
SKU 商品毛利润 → 链接贡献利润 → 产品整体汇总
        ↓
7 天调价观察与运营建议
```

领域计算与页面渲染分开：

- `domain`：实体、状态机、有效版本解析、利润和观察期计算。
- `repository`：演示内存仓库；后续替换云端仓库时保持同一接口。
- `selectors`：产品整体、链接详情、待填写和观察中视图模型。
- `ui`：录入表、汇总、展开历史和设置抽屉。

不得将演示数据生成、DOM 事件和利润公式继续堆在单一文件中。

## 10. 异常、校验与审计

- 售价、销量、费用不得为负。
- 销量必须为整数；金额统一货币精度。
- 日期按链接时区生成，避免跨时区错日。
- 产品整体跨币种汇总必须先有明确汇率口径；本轮演示限定同一货币。
- 重复的链接 SKU 日报由唯一约束阻止。
- 成本或佣金缺失时显示“利润口径不完整”，不得静默按 0 计算。
- 已完成日报修改后保留修改人、时间和修改前值。
- 下架和停用不删除历史。
- URL 变更保留版本；平台 Listing ID 变化通常创建新链接并关联前序链接。

## 11. 响应式与排版

- 桌面端：产品整体使用链接比较表；单链接使用紧凑 SKU 当日填写表。
- 中等宽度：表格自身滚动，SKU 列固定，页面不横向溢出。
- 手机端：产品链接行转为摘要卡；SKU 行转为当前日双输入卡，7 天历史按需展开。
- 数字统一使用等宽数字；金额、数量、百分比列上下左右对齐。
- 短标签不拆字；长链接截断并提供打开入口。
- 不使用重复 KPI 大卡片和装饰性英雄区挤占首屏。

## 12. 测试与验收

### 12.1 领域测试

- 同产品多店多链接独立定价。
- 链接 SKU 覆盖成本和公共成本回退。
- 成本 / 佣金版本按日期生效且历史快照不变。
- SKU、链接和产品三层汇总精确。
- 下架日期前后汇总范围正确。
- null 与 0 销量严格区分。
- 三套状态机互不污染。
- 调价基线、观察窗、数据不足和链接间转移判定。

### 12.2 交互测试

- 产品整体进入链接详情。
- 今日 SKU 连续键盘填写。
- 修改售价即时刷新 SKU 与链接贡献利润。
- 调价观察创建、进行、复盘和结束。
- 新链接继承旧链接关系但不继承每日事实。
- SKU 停用后历史仍可查看。
- 未填写项和完成度校验。

### 12.3 页面验收

- 运营进入产品整体后能在 10 秒内识别最需要处理的链接。
- 进入链接后无需横向查看 7 天大表即可完成当日全部 SKU 填写。
- 单个 SKU 可按需展开近 7 天售价、销量和利润。
- 计划性调价与真实利润风险不会混淆。
- 产品整体可以识别同品不同链接的增长、分流和下架状态。
- 桌面和 320px 窄屏均无页面级横向溢出、孤字或缺字。

## 13. 本轮不包含

- Excel 导入或自动同步 TikTok 数据。
- 正式云端写入、多人冲突合并和权限后台。
- 严格因果实验或自动调价。
- 跨币种汇率换算。
- 公司固定成本、税务和真正公司净利润。

这些能力必须在本模型稳定并完成团队试用后独立设计，不能通过继续向每日表格增加字段实现。
