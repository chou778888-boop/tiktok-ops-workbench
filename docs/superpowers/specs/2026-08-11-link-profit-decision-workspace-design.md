# 单条链接利润经营决策页设计

## 目标

将现有“链接利润详情”从并列展示指标、趋势、账本、SKU 和费用录入的综合数据页，重构为团队可以直接完成判断与处理的单条链接经营决策页。

页面进入后应按固定顺序回答四个问题：

1. 这条链接当前赚了多少，结论是暂算还是真实最终利润？
2. 结果主要由哪些收入、成本和 SKU 造成？
3. 当前还缺什么数据或存在什么异常？
4. 运营人员下一步应该执行什么动作？

本次不改变利润公式、真实数据、云端存储或产品—链接—SKU 关系，只调整单条链接详情的信息架构、默认展示层级、交互与视觉表达。

## 三方设计判断

### ChatGPT：信息架构与认知负担

- 页面阅读顺序固定为“结果 → 原因 → 动作 → 证据”。
- 同一个经营结论不得通过多张同权重卡片重复表达。
- 使用渐进披露：首屏只保留影响判断和行动的信息，完整趋势、全部 SKU、设置与历史按需展开。
- 状态文案必须解释结论的可信度，不能只显示颜色或模糊标签。

### 跨境电商运营：经营口径与行动闭环

- 首先区分“暂算利润”和“最终利润”。广告、样品或调整费用缺失时禁止显示为最终利润。
- 成交均价与实际到手保持独立：成交均价用于判断价格和动销，实际到手只反映扣除运费与平台费用后的结算金额。
- 产品成本、广告、样品和其他调整在实际到手之后单独核算，禁止重复扣减。
- SKU 层只显示商品毛利，不把链接层平台费用伪分摊到 SKU。
- 数据不完整时不生成误导性趋势或环比结论。
- 每种状态都必须落到明确动作，例如补齐费用、核对结算差异、处理利润拖累或查看经营建议。

### 网页设计：层级、密度与交互

- 页面只能有一个主要视觉焦点：经营判断卡。
- 深墨绿只用于最终结果和主操作；琥珀表示待补或不完整；红色只表示亏损或严重异常。
- 桌面端采用有意图的不对称布局，避免平均分配空间的卡片矩阵。
- 主体文字不小于 14px，辅助标签不小于 12px；关键金额 32–36px，辅助金额 18–22px。
- 卡片使用边框或阴影其中一种，避免层层套卡。
- 所有按钮具备 hover、focus、active、loading 和 disabled 状态；移动端触控区域不小于 44px。

## 页面结构

### 1. 紧凑上下文栏

将现有大面积链接标题卡收为一条上下文栏，保留：

- 面包屑：产品总盘 / 产品整体 / 当前链接。
- 产品名称、店铺、链接 ID、负责人。
- 经营日期与链接生命周期状态。
- 打开商品页、链接与 SKU 设置。

经营日期融入右侧工具区。商品页和设置为次级操作，不与经营动作争夺主按钮。

### 2. 经营判断卡

经营判断卡是首屏唯一强强调区域，包含：

- 主结论：暂算盈利、最终盈利、亏损、待同步或待核对。
- 主金额：暂算或最终利润。
- 利润率。
- 实际到手。
- 数据完整度：平台结算、广告费用、样品费用、其他调整的完成状态。
- 一句可执行判断，不重复罗列所有指标。
- 一个随状态变化的主按钮。

GMV、成交均价、销量和产品成本保留为卡片底部的紧凑辅助指标行，不再拆成五张同权重 KPI 卡。

主按钮规则：

| 当前状态 | 主按钮 |
|---|---|
| 广告、样品或调整费用缺失 | 补齐费用 |
| 结算差异超出容差 | 核对结算差异 |
| 最终利润为负 | 查看利润拖累 |
| 利润率低于经营阈值 | 查看改善机会 |
| 数据完整且利润健康 | 查看经营建议 |
| 店铺数据未同步 | 查看同步状态 |

多个状态同时出现时按“数据待同步 → 链接与 SKU 汇总异常 → 费用待补 → 亏损 → 低利润 → 健康”确定唯一主动作。Product Analytics GMV 与 Earnings Analytics 平台确认销售额的口径差只作为账本说明，不单独覆盖主动作。低利润沿用当前低于 8% 的经营阈值。同一区域只允许一个主按钮；商品页、设置和历史记录均使用次级或文字按钮。

### 3. 利润形成与 SKU 原因

桌面端使用 40% : 60% 双栏，窄屏按顺序堆叠。

#### 左栏：利润形成过程

使用单层财务账本或瀑布式表达：

1. 经营 GMV。
2. 平台确认销售额，仅在与经营 GMV 存在差异时显示。
3. 平台订单成本，包括运费及平台各项费用。
4. 实际到手。
5. 产品成本。
6. 广告、样品及调整。
7. 暂算或最终利润。

平台确认销售额与经营 GMV 无显著差异时隐藏差异层，减少日常噪声。金额按财务语义右对齐，扣减项使用统一负号格式，不依靠颜色表达正负。

#### 右栏：SKU 经营贡献

默认显示最多三类重点 SKU：

- 商品毛利贡献最高。
- 商品毛利最低、亏损或价格异常。
- 零销量、数据待同步或经营异常。

默认列为：SKU / 规格、成交均价、销量、SKU 商品毛利、经营信号。完整表格展开后补充 SKU GMV、销量成本和近七日摘要。

当同一 SKU 同时属于多类重点时只显示一次，并按“亏损/异常 → 零销量 → 低毛利 → 高贡献”排序。无异常时展示贡献最高的前三个 SKU。

“查看全部 N 个 SKU”展开完整表格；零销量 SKU 不在首屏占据与主力 SKU 相同的空间。

## 七日趋势规则

趋势属于经营证据，不是首屏主结论。根据完整数据日数量控制展示：

| 完整数据日 | 展示规则 |
|---:|---|
| 0 | 显示等待同步的空状态，不绘制图表 |
| 1–2 | 显示“数据不足，暂不形成趋势判断”，只列已同步日期 |
| 3–6 | 显示紧凑趋势摘要，标记周期未完整，不生成环比结论 |
| 7 | 显示成交均价折线与销量柱，并生成价格、销量变化判断 |

完整七日趋势默认以紧凑摘要呈现，用户点击后展开完整图表。更早历史保持收起。空缺日期必须明确显示待同步，不用零值连接折线。

## 费用补录交互

点击“补齐费用”打开右侧抽屉，桌面宽度 400–480px，移动端全宽。抽屉包含：

- 标准寄样数量及单份成本。
- 广告费。
- 其他调整费用。
- 补录前后利润变化预览。
- 保存并确认最终利润。

输入采用单列排列和可见标签。空白继续表示待补，不自动视为 0；确实无费用时必须明确填写 0。保存失败时保留用户输入并显示字段级错误；保存成功后关闭抽屉、恢复焦点并刷新判断卡，不进行整页重载。

链接生命周期和 SKU 管理继续使用独立的“链接与 SKU 设置”抽屉，不与费用补录混合。

## 状态与异常处理

### 数据待同步

- 主结论显示“今日数据待同步”。
- 使用最近一个完整经营日作为参考，但必须标明日期，不计入今日判断。
- 禁用依赖今日数据的利润动作，保留同步状态入口。

### 费用待补

- 显示暂算利润和琥珀色完整度状态。
- 明确列出缺失项目。
- 主操作为补齐费用。

### 对账差异

- 链接汇总与 SKU 汇总差异绝对值达到当前 0.01 美元容差时，升级为需要处理的异常。
- 经营 GMV、平台确认销售额和两者口径差在存在差异时继续展示，但不默认判定为数据异常。
- 不自动修改任何来源数据，提供核对入口。

### 亏损或低利润

- 亏损使用红色结果状态，并优先展示最大成本项和最低商品毛利 SKU。
- 低利润使用中性或琥珀提示，不与真实亏损混用。
- 系统建议必须来自可验证数据，不使用泛化运营话术。

### 无 SKU 或链接下架

- 无 SKU 时显示就地空状态和“进入链接设置”按钮。
- 暂停、下架和归档链接仍可查看历史利润，但编辑和同步动作按现有生命周期规则限制。

## 响应式布局

### 桌面端（大于 900px）

- 上下文栏、经营判断卡、40/60 原因双栏、趋势摘要依次排列。
- 完整 SKU 表格在自身容器内滚动，不允许页面整体横向溢出。
- 费用与设置使用右侧抽屉。

### 平板端（641–900px）

- 利润形成与 SKU 原因改为单列。
- 判断卡辅助指标使用两列网格。
- 趋势图保持可读宽度，不压缩日期文字。

### 窄屏（约 320–640px）

- 顺序固定为：经营结论 → 主操作 → 利润形成 → 重点 SKU → 趋势摘要 → 次级入口。
- SKU 默认使用条目卡，不把七列表格强行压进屏幕。
- 抽屉全宽，输入单列，按钮文案完整且触控高度不小于 44px。
- 页面不得整体横向滚动；只有显式展开的完整数据矩阵可以内部横向滚动。

## 代码结构与数据流

保留现有利润领域模型、仓储和选择器边界：

- `61-profit-domain.js` 继续负责纯利润计算。
- `62-profit-repository.js` 继续负责链接、SKU、费用和结算数据访问。
- `63-profit-selectors.js` 输出页面所需的经营判断数据，不在模板中重复计算业务结论。
- `65-profit-template.js` 仅负责视图状态、渲染和交互绑定。

新增或整理为可独立测试的视图模型：

- 链接经营结论模型：主结论、可信度、主动作和辅助指标。
- SKU 重点排序模型：异常去重、优先级和默认展示数量。
- 趋势可用性模型：完整日数量、可否生成趋势及环比。
- 利润形成模型：按业务口径决定可见账本行，不改变金额计算。

视图只消费这些模型，不根据 CSS 状态或文案反推业务逻辑。费用保存沿用现有云端持久化机制，不创建新的数据副本。

## 加载、保存与错误反馈

- 初次进入使用与最终布局一致的骨架屏；预计 300ms 内完成时不闪现加载动画。
- 日期或链接切换后只更新利润详情区域，不重建整个工作台。
- 保存按钮进入明确的加载状态并防止重复提交。
- 云端保存失败时保留表单内容，显示可重试错误，不回滚为伪造的 0。
- 数据源缺失、结算未返回和真实零值必须使用不同状态表达。

## 测试与验收

### 业务逻辑

- 成交均价与实际到手分别计算和展示。
- 平台费用只在链接层核算，不进入 SKU 商品毛利。
- 广告、样品和调整缺失时只生成暂算利润。
- 所有内部费用明确填写后才生成最终利润。
- 不完整七日数据禁止生成完整周期环比。
- SKU 重点排序可稳定处理亏损、零销量、重复异常和全部健康状态。

### 交互

- 产品总盘 → 产品整体 → 单条链接的下钻和返回路径保持可用。
- 补齐费用、保存、取消、Escape、焦点恢复和失败重试正常。
- 查看全部 SKU、展开趋势、打开商品页、链接设置和生命周期操作正常。
- 空状态、异常状态、待同步、费用待补、结算差异、亏损和健康状态均有真实回归样例。

### 视觉与响应式

- 1440×900 首屏能看到经营结论、主动作、利润形成和重点 SKU。
- 经营结论是唯一强视觉焦点，没有五张同权重 KPI 卡。
- 仅有 1–2 个完整数据日时不出现占据半屏的空趋势图。
- 长产品名、动态金额、两位数 SKU 数量和不同状态文案不产生孤字或按钮截断。
- 900px、640px、390px 和约 320px 均无页面整体横向溢出。
- 数字列按语义右对齐，表头与内容对应清晰。

## 明确不做

- 不修改利润公式或业务口径。
- 不覆盖、重置或批量改写真实团队数据。
- 不把利润分析拆成多个需要频繁跳转的独立页面。
- 不增加新的装饰性图表、重复 KPI 卡或无操作价值的状态标签。
- 不把日报中心、任务中心或成本测算逻辑混入链接利润详情。
