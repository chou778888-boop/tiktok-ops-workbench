# 利润中心可交互模板设计

## 目标

在现有“成本测算”模块内新增“利润中心 · 模板”页签，让用户直接预览未来的商品链接、SKU 和利润管理方式。模板支持新增商品链接、新增 SKU、停用 SKU 和恢复 SKU，但所有变更只保存在当前页面内存中；刷新后恢复示例数据，不写入本地存储、云端状态或 D1。

## 范围

- 沿用当前工作台的导航、颜色、字体、按钮和卡片语言。
- 使用 JZZ、JDZ、牙贴等虚拟示例数据，不读取 Excel。
- 展示销量、GMV、样品费、广告费、实际利润、利润率六个指标。
- 按“店铺 → 商品链接 → SKU”展示商品结构。
- 展示 SKU 级销量、售价、成本、佣金率、实际利润和状态。
- 对负利润、停用 SKU 和缺少链接的信息给出清晰状态提示。

本次不实现云端保存、Excel 导入、真实利润计算、历史追溯、批量编辑或权限控制。

## 页面结构与排版

模板作为成本测算的第四个子页签，名称为“利润中心 · 模板”，并带“预览”标识。

页面从上到下分为四层：

1. 页面标题和操作区：左侧说明模板用途，右侧放“新增商品链接”主按钮；按钮不与标题抢占同一视觉层级。
2. 指标区：六张紧凑指标卡使用响应式网格。宽度不小于 1440px 时一行六列，900–1439px 时两行三列，420–899px 时三行两列，更窄时单列，不横向挤压。
3. 商品链接区：以店铺分组，每个链接使用独立卡片；链接名称、店铺、URL 和状态在顶部，SKU 列表在下方。主操作固定在卡片右上角。
4. SKU 利润表：桌面端完整展示，窄屏允许表格自身横向滚动，不让整个页面横向溢出。

视觉要求：卡片间距一致；数据列右对齐；状态只使用少量语义色；负利润用红色文字和浅色底提示，不使用大面积高饱和红色；按钮分为主操作、次操作和危险操作三个层级。

## 交互

“新增商品链接”打开轻量模态表单，填写店铺、产品名称和商品 URL。提交后关闭表单，将演示链接插入当前页面并展开。

每张链接卡片提供“新增 SKU”。SKU 表单包含名称、售价、单件成本和佣金率；提交后即时加入该链接，并根据模板公式生成演示利润数据。

SKU 不执行硬删除。“停用”后保留在列表中并显示停用状态；“恢复”可重新启用。默认统计只汇总启用 SKU，避免用户误以为历史数据被删除。

表单校验只覆盖模板必要字段：产品名、合法 URL、SKU 名称、非负售价和成本、0–100% 佣金率。错误显示在对应字段附近，并保留已输入内容。

## 数据与隔离

模板数据由利润中心模块内的工厂函数创建，每次页面初始化生成新的内存对象。模板不调用 `saveState()`，不修改 `state.products`、`state.costProfiles` 或任何 API。新增和停用操作只更新模板自己的内存数组并重新渲染。

利润展示采用简化演示公式：

```text
单件利润 = 售价 × (1 - 佣金率) - 单件成本
SKU 实际利润 = 单件利润 × 销量 - 样品费 - 广告费
```

页面明确标注“示例数据，不会保存”，避免与真实经营数据混淆。

## 代码边界

- HTML 容器和子页签入口放在 `index.html` 的成本测算区域。
- 模板业务与交互放在新的 `src/app/workbench/65-profit-template.js`，不扩大现有成本计算文件。
- 模板样式放在新的 `src/styles/modules/18-profit-template.css`。
- 新文件登记到应用与样式构建清单，确保构建产物包含模板。
- 现有 `60-costing.js` 只保留已有成本业务，不承载模板状态。

## 验证标准

- “成本测算”中可切换到“利润中心 · 模板”，现有三个页签不受影响。
- 新增链接、新增 SKU、停用和恢复均可在当前页面完成。
- 刷新后恢复初始示例，云端和本地业务数据不发生变化。
- 桌面端信息层级清楚；窄屏下指标卡不挤压，利润表仅在自身区域滚动。
- 构建检查、模块边界检查和现有自动化测试全部通过。
