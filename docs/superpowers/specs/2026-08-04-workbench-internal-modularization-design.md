# 工作台底层模块化设计

## 目标

在功能、界面、交互、接口、数据结构和线上加载方式完全不变的前提下，把当前集中在 `src/app/workbench.js` 的业务代码整理为职责单一、可独立检查的源码模块，降低以后修改日报、任务、成本或达人功能时的影响范围。

## 不在本次范围内

- 不改变任何可见文案、排版和交互。
- 不新增、删除或调整业务功能。
- 不修改 Cloudflare D1 表结构或团队真实数据。
- 不引入 React、Vue 或新的运行时依赖。
- 不增加线上 JavaScript 请求数量。
- 不顺带清理现有用户文件或无关 Git 修改。

## 方案

采用渐进式等价拆分。源码按模块维护，构建时按照经过检查的固定顺序合并，生产环境仍加载一个带版本指纹的压缩 JavaScript 文件。

不直接改成浏览器 ES Modules。现有逻辑共享较多闭包状态，一次改变执行模型容易造成初始化顺序、事件绑定和状态引用差异。先完成物理拆分和依赖显式化，未来确有需要时再单独评估模块运行时迁移。

## 模块职责

### 启动层

`boot.js` 继续负责登录、单请求 bootstrap、主脚本按需加载和启动性能记录。完整工作台模块不得重新引入启动阶段的重复用户或状态请求。

### 核心层

- `config.js`：店铺、岗位、任务状态、分页数量及其他稳定业务常量。
- `runtime.js`：当前页面、筛选器、展开项、同步状态等运行期可变状态。
- `state.js`：默认数据、标准化、本地备份和集合唯一性规则。
- `cloud-sync.js`：增量补丁、版本冲突保护、定时刷新和保存队列。
- `dates.js`：本地日期、周期范围、上期比较和逾期判断。
- `format.js`：金额、数字、日期时间、文本与 HTML 安全格式化。

核心层不引用具体页面 DOM。业务模块可以使用核心层能力，但不能反向成为核心层依赖。

### 业务层

每个业务模块包含本板块的数据计算、渲染和操作逻辑。任务与日报允许通过明确的共享函数互相调用，因为日报提交会生成任务、任务复查会回到日报；这条关系必须在依赖清单中记录，不能依靠隐藏的执行顺序。

### 界面协调层

导航、通用图表、表单辅助和全局事件委托放在 `ui/`。具体业务表单的校验和数据采集仍归所属业务模块，避免形成新的通用巨型文件。

## 构建与执行顺序

新增 `scripts/app-sources.mjs` 作为唯一源码清单。`scripts/build-cloudflare.mjs` 从该清单读取并合并文件，再执行现有版本哈希、压缩和单文件输出。

源码清单必须执行以下检查：

1. 所有声明文件存在且不重复。
2. 入口文件必须最后执行。
3. 未列入清单的应用源码会使检查失败，防止新增文件未进入生产构建。
4. 合并后的有效源码与迁移前基准保持一致；只允许模块边界注释和构建所需包裹产生的差异。
5. 生产输出继续只有 `boot-<release>.js` 与 `workbench-<release>.js` 两个脚本。

## 数据安全

- 重构期间不运行任何远程 D1 写入、初始化或 migration。
- 本地预览只使用现有本地数据库或只读线上验证。
- `functions/api/state.js` 的增量补丁、revision 与任务状态防回退规则保持不变。
- 数据标准化规则迁移后必须使用相同输入输出夹具做深度相等检查。
- 构建和部署脚本不得包含业务数据初始化步骤。

## 迁移顺序

1. 建立应用源码清单、合并器和等价性测试。
2. 抽离低耦合工具：日期、格式化和稳定配置。
3. 抽离状态标准化与云端同步。
4. 依次抽离总览、任务、日报、成本、达人和学院。
5. 最后整理导航、通用 UI 和事件绑定，使 `workbench.js` 只保留入口包裹与初始化。

任务在日报之前迁移，但两者必须作为同一验证阶段检查，避免破坏日报生成任务与到期任务复查链路。

## 验证标准

每个阶段必须同时通过：

- 所有 JavaScript 语法检查。
- 现有项目检查及全部业务回归测试。
- 新增源码清单顺序、重复声明和缺失文件检查。
- 构建成功且生产脚本数量不变。
- 登录恢复、总览、日报、任务、成本、达人关键交互验证。
- 桌面端和移动端无控制台错误。
- 不存在远程 D1 写入或业务数据变化。

如某阶段无法证明等价，则停止该阶段并保留上一阶段已验证结构，不扩大修改范围。

## 文档交付

同步更新：

- `docs/ARCHITECTURE.md`：最终目录、模块依赖和数据流。
- `docs/CHANGE_GUIDE.md`：不同需求对应的修改文件、检查命令和本地预览流程。
- `docs/SECURITY.md`：重构和部署的数据安全边界。
- 新增模块清单说明：每个文件的职责、公开依赖和禁止依赖。

## 完成定义

- `workbench.js` 不再承载全部业务实现，仅作为清晰入口。
- 各业务板块可以通过文件路径直接定位。
- 构建仍输出一个完整工作台脚本，线上加载行为不变。
- 功能、界面、数据结构和团队数据均未改变。
- 新维护者只阅读架构与修改指南，即可判断应该修改哪里、运行哪些检查以及如何安全发布。
