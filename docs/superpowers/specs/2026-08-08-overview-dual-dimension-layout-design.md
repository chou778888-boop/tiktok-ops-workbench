# 总览近 7 日双维度同屏设计

## 目标

把“近 7 日经营变化”从桌面端单维度切换改为同屏双维度判断：左侧展示店群 GMV 与来源变化，右侧展示重点链接价量与利润动作。两者处于同一经营判断层级，但不混用日期口径，不重复表达同一指标。

## 已确认的设计决策

- 桌面端两个维度同时可见，不需要切换后才能看到另一维度。
- 外层采用接近等分的 `52% / 48%` 基础比例。店群趋势需要更长的时间轴，因此略宽；重点链接内容更密集，但不依赖更长画布。
- 两列等高并由内容自然撑开，不设置为了“看起来大”而产生空白的固定高度。
- 左侧保留多店 GMV 主趋势；来源贡献由独立窄侧栏改为卡片内的紧凑横向摘要，避免在半宽列中继续二次切割。
- 右侧保留重点链接成交均价与销量趋势；实际到手、暂算利润、有效数据和处理动作集中到图表下方的紧凑决策区。
- 两侧分别显示自己的真实数据周期。店群周期与链接周期不同时必须明确标注，不得使用一个公共日期徽标暗示统一口径。
- 不把“近 7 天销量”和“近 7 天 GMV”再次拆成上下两个大型模块；它们是维度内部的辅助指标，不是新的主区块。

## 桌面布局

### 左侧：店群经营变化（52%）

1. 标题、店群真实周期与完整周期比较状态。
2. GMV 日趋势占据卡片的主要面积。
3. 来源贡献压缩为图表下方的横向结构：主增长来源、联盟 GMV、商品卡、未归类成交、广告归因。
4. 广告归因继续单独标明，不重复计入交易来源占比。

### 右侧：重点链接价量（48%）

1. 标题、产品/店铺/链接路径与链接真实周期。
2. 成交均价和销量共用一张趋势图。
3. 图表下方展示销量、GMV、实际到手、暂算/最终利润和费用状态。
4. “处理此链接”作为该卡片唯一主操作，直接进入链接利润明细。

### 空间规则

- 外层基准为 `minmax(0, 1.04fr) minmax(420px, 0.96fr)`，不是僵硬像素宽度。
- 内容较少的摘要使用横向行或 2×2 指标网格，不单独占用大块空间。
- 文本允许合理换行，但标题、数字、SKU 与动作标签不得出现孤字或无意义断行。
- 两列底部允许因真实数据略有差异，但不得依靠大面积空白强行完全等高。

## 响应式

- 宽度大于等于 1180px：双维度同屏。
- 760px 至 1179px：保留当前分段切换，单次只展示一个维度，保证图表长度。
- 小于 760px：继续使用分段切换；指标压缩为两列，操作按钮满宽，页面不得产生横向溢出。

## 数据与交互

- 不修改现有数据模型、云端持久化、利润计算和日期筛选逻辑。
- 桌面端两个画布都需要在数据变化、日期变化和窗口尺寸变化时正确重绘。
- 窄屏切换只控制展示状态，不销毁数据，不改变当前日期筛选。
- 店群 GMV 的周期比较仍遵守“前 7 个完整自然日”；上周期不完整时继续禁止输出误导性环比。

## 验收标准

- 1440px 桌面端同时看见店群 GMV 和重点链接价量，两列接近等分且没有明显无意义留白。
- 两侧日期分别匹配真实数据：示例店群为滚动店群周期，示例链接为 `2026-07-28—2026-08-03`。
- 来源贡献在半宽左卡中仍可读，不出现第三层狭窄侧栏。
- 重点链接卡可看到价量趋势、实际到手、利润状态与处理入口，不需要额外展开。
- 1179px 以下仍能可靠切换两个维度；390px 页面宽度等于视口宽度。
- 今日、昨日、近 7 日、近 30 日和指定日期均不破坏布局或日期口径。
- 现有真实数据、风险跳转和利润入口保持可用。

## 非目标

- 不重做总览顶部整体经营判断。
- 不修改利润核算公式或产品/链接/SKU 数据结构。
- 不把日报中心与任务中心逻辑并入总览。
