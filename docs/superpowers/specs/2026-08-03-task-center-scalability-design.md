# 任务中心扩容与双视角设计

## 背景

当前任务中心按照“待处理、处理中、待复盘、已归档”四个状态一次性展示全体任务。任务数量增加后，员工难以快速定位本人当前任务，管理者也难以按负责人识别积压与逾期。已完成和已作废任务继续占据主工作区，还会进一步增加视觉负担。

本次优化只调整任务中心的读取、筛选、分组和展示方式，不修改现有任务状态流转、日报复查逻辑、D1 数据结构或团队真实数据。

## 目标

1. 员工进入任务中心后，优先看到本人当前需要处理的任务。
2. 管理者能够按负责人查看团队任务量、进度、待复盘和逾期情况。
3. 已完成与已作废任务退出日常工作视野，但仍可搜索和追溯。
4. 桌面端、Windows、Mac 和移动端保持统一且清晰的视觉层级。
5. 复用现有设计令牌、CSS 分层和样式模块，不引入独立视觉体系。

## 选定方案

采用前端视图优化方案。所有视图继续读取同一批现有任务数据，通过客户端筛选、排序和分组形成“我的任务”“团队任务”“历史任务”三个入口。

该方案不新增人员表、不迁移任务、不增加 D1 查询接口，能够以最小数据风险解决当前任务过多的问题。

## 信息架构

任务中心顶部提供三个入口：

- **我的任务**：默认入口，显示与当天日报姓名匹配的未终态任务。
- **团队任务**：按负责人分组显示全部未终态任务。
- **历史任务**：显示已完成和已作废任务，默认不进入当前任务视野。

任务快速创建功能保持不变。现有任务编辑、开始处理、提交执行结果、待复盘、关闭、继续、升级和作废流程保持不变。

## 当前人员识别

“我的任务”使用日报中心当天填写的姓名作为当前人员身份，不在任务中心重复设置姓名。

- 姓名匹配沿用现有标准化规则：去除首尾空格并忽略英文大小写。
- 当天日报姓名为空时，不显示任何人的私人任务。
- 空姓名状态显示明确提示和“前往日报中心填写姓名”操作。
- 不使用历史姓名自动猜测当前人员，避免共享设备上误显示其他成员任务。

该身份只用于前端任务筛选，不等同于账号权限或安全认证。

## 我的任务

“我的任务”只显示负责人姓名与当天日报姓名匹配、且状态不是已完成或已作废的任务。

顶部显示三个紧凑摘要：今天需要处理、处理中、待复盘。摘要用于快速理解任务分布，不新增业务指标。

任务排序规则依次为：

1. 已逾期任务；
2. 紧急任务；
3. 截止时间较早的任务；
4. 无截止时间的任务；
5. 更新时间较新的任务。

任务卡默认显示标题、来源、负责人、优先级、截止时间和状态。处理要求、验收标准、执行结果和证据继续通过“展开详情”查看，避免卡片过长。

## 团队任务

“团队任务”按负责人分组，不再把所有人的任务直接混排在状态列中。

每个负责人组显示：

- 姓名；
- 未完成任务总数；
- 逾期数量；
- 处理中数量；
- 待复盘数量。

负责人组默认收起，存在逾期任务的负责人优先排列。展开后，组内任务使用与“我的任务”相同的排序和任务卡操作，保证使用习惯一致。

未填写负责人的任务统一归入“未分配”组并优先提示。团队视图提供搜索，以及状态、优先级和逾期条件筛选；筛选仅改变展示，不修改任务。

## 历史任务

已完成和已作废任务从“我的任务”和“团队任务”中移除，统一进入“历史任务”。

历史任务支持按关键词、负责人、结果状态和日期范围查找。每条记录继续保留执行结果、证据、复查结论、作废原因和操作记录。

历史任务初始只呈现有限数量，后续通过“加载更多”逐批显示，避免一次渲染大量旧任务。第一阶段采用前端分批展示，不调整后端接口。

## 状态与边界情况

- 没有日报姓名：显示身份提示，不回退到团队全量任务。
- 当前人员没有任务：显示“当前没有分配给你的未完成任务”，并保留团队任务入口。
- 负责人姓名只有大小写或首尾空格差异：视为同一人。
- 相似但不完全相同的姓名：视为不同人员，不做模糊匹配。
- 未分配任务：不进入任何人的“我的任务”，只进入团队任务的“未分配”组。
- 已完成或已作废任务：只进入历史任务。
- 任务状态在其他页面被更新：沿用现有云端状态同步机制，重新渲染三个视图。

## 视觉与响应式设计

正式界面不照搬线框稿，而是基于当前工作台的设计系统完成统一排版。

- 颜色、字体、间距、圆角、边框、阴影、徽章和按钮全部使用现有设计令牌。
- 新样式放入现有有序 CSS 模块体系，构建后仍产出单一生产 CSS。
- 桌面端使用清晰的视角切换、负责人摘要行和可展开任务组。
- 移动端采用单列布局；摘要自动换行，负责人组和任务详情不产生横向溢出。
- 逾期、紧急和待复盘通过文字与现有状态样式共同表达，不只依赖颜色。
- 键盘焦点、按钮语义、展开状态和空状态提示保持可访问。

## 数据与安全约束

- 不删除、覆盖或重置任何现有任务及日报数据。
- 不修改 D1 表结构和线上真实团队数据。
- 不改变任务状态同步版本和冲突处理规则。
- 不把“我的任务”姓名筛选描述为安全权限；真正权限控制不在本次范围。
- 部署只更新 Pages 代码与静态资源。

## 验证标准

自动检查至少覆盖：

1. “我的任务”只匹配当天日报姓名与未终态任务；
2. 姓名标准化规则正确；
3. 空姓名不会泄露团队任务；
4. 团队任务按负责人正确分组并统计状态；
5. 未分配任务进入独立分组；
6. 已完成和已作废任务只进入历史任务；
7. 逾期、优先级和截止时间排序稳定；
8. 现有任务状态同步测试继续通过。

浏览器回归至少覆盖桌面端与 390px 移动端，验证三个入口、筛选、负责人组展开、任务操作、空状态、历史任务加载和无横向溢出。生产构建、项目检查和 JavaScript 语法检查必须通过。

## 发布流程

严格遵循：本地实现 → 本地自动检查 → 本地浏览器回归 → 用户预览确认 → 用户明确要求同步云端 → 发布正式生产分支 → 核对正式域名 release。

用户确认前不部署。发布过程只更新代码，不直接操作 D1 或团队真实数据。
