# 总览首屏紧凑经营指挥台设计

日期：2026-08-08  
状态：用户已确认  
范围：总览首屏标题、日期筛选、经营焦点与七日趋势，不改变数据、计算和跳转逻辑

## 问题

当前总览在顶部使用大字号口号、说明、日期上下文和独立日期筛选区。宽屏下文字仅占左侧小部分，右侧形成大面积无效留白；用户需要先跨过展示性内容，才能看到真正要处理的经营链接。

经营焦点面板内部又重复展示“实际到手”和“暂算利润”，七日趋势在只有一个有效数据日时仍保持大面积深色图表，造成视觉权重与信息价值不匹配。

## 设计目标

- 打开工作台后直接进入经营判断，不先经过营销式 Hero。
- 日期筛选属于总览数据上下文，融入经营焦点主表面顶部，不单独占行。
- 首屏唯一主角是“今天最该处理的产品链接”；GMV、利润和趋势用于支撑判断。
- 保留信息密度和高级质感，使用精确栅格、克制材质、清晰层级和稳定交互反馈。
- 真实数据不足时主动收缩图表表达，不用空图撑满空间。

## 桌面结构

### 一、经营控制栏

`overview-focus-surface` 顶部新增一条约 56px 的连续控制栏：

- 左侧显示当前数据上下文，如“今日经营总览 · 2026-08-08”。
- 右侧依次放置“今日、昨日、近7日、近30日”和日期选择器。
- 当前口径说明放在控制栏下沿或左侧上下文的次级文字中，不再独占一行。
- 控制栏与面板共用边框、圆角和底色，不制造新的悬浮卡片。

### 二、经营主体

控制栏下方保持左右布局，但调整为约 46:54：

- 左侧：经营状态、重点链接标题、判断说明、产品/店铺/链接/SKU 路径、实际到手、暂算利润和“处理此链接”。
- 右侧：七日成交均价与销量趋势、数据更新时间和不重复的辅助指标。
- 价格、动销、动作判断继续作为左侧底部连续信息条，不单独占用外部行。

### 三、指标去重

- “实际到手”和“暂算利润”只在左侧经营决策区展示一次。
- 趋势区底部改为“近7日销量、近7日GMV、有效数据天数、费用完整度”等不重复指标。
- 同一数值不得因视觉填充在左右两侧重复出现。

### 四、数据不足状态

- 有效数据少于两个自然日时，不绘制具有趋势暗示的完整折线。
- 图表区高度收缩，显示已有数据日、缺失天数、下一次同步时间和补齐入口。
- 有两个及以上有效数据日时恢复完整趋势图。

## 视觉语言

- 取消大字号口号和荧光下划线，页面不再使用营销官网式 Hero。
- 主面板使用浅灰绿连续表面、1px 低对比边框和短距离柔和阴影。
- 深墨绿仅用于内嵌图表、主按钮和关键状态，荧光绿仅用于趋势点、健康状态和焦点反馈。
- 标题、正文、数字和辅助信息使用清晰的四级层次，金额与销量使用等宽数字。
- 控件高度、圆角、边框和选中状态与顶部导航及其他业务模块保持一致。

## 响应式

- 1180px 以上：控制栏左右分布，经营主体左右并列。
- 761–1180px：控制栏仍保持一行；经营主体改为上下排列，但仍属于同一表面。
- 760px 以下：上下文与日期筛选分成紧凑两行，快捷日期保持四列，日期选择器全宽。
- 320px 宽不得产生页面级横向滚动；长链接标题最多两行，路径安全省略。

## 保持不变

- 不修改日期范围计算、利润计算、Canvas 数据、同步逻辑和跳转目标。
- 不修改云端或本地业务数据。
- 不删除日期选项、经营判断、利润摘要、七日趋势和处理入口。
- 不引入 React、Figma 运行时、GSAP 或新的生产依赖。

## 验收标准

- 1440px 与 1920px 首屏不再出现大面积标题留白，经营焦点明显上移。
- 日期筛选完全位于经营主表面内部，不再单独占据页面行。
- “实际到手”和“暂算利润”各只出现一次。
- 只有一个有效数据日时图表进入紧凑数据不足状态；两天及以上恢复趋势表达。
- 1280px、760px、390px、320px 无横向溢出、孤字和少字换行。
- 所有原有按钮、日期筛选、趋势、状态和利润跳转可用。
- 聚焦测试、完整项目检查、生产构建和真实浏览器交互回归通过。
