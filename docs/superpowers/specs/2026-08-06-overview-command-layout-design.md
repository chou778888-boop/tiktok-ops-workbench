# 总览首屏「一屏经营指挥台」排版设计

日期：2026-08-06
状态：方向 A 已由用户确认
范围：仅重排工作台总览首屏；不修改利润公式、数据结构、导航功能和次级业务页面

## 1. 设计结论

当前首屏难看的根因不是颜色或质感不足，而是三个区域彼此争夺主视觉：超大标题占用左侧大量空间，利润焦点悬在右侧，七天趋势又以整块深色区域压在下方。页面虽然有设计元素，但缺少一条连续的经营判断路径。

新排版采用“一屏经营指挥台”：左侧回答“今天处理哪条链接、利润是多少”，右侧回答“近七天价格和动销怎么变化”，并在同一屏给出下一步动作。标题退回导航角色，不再占据近半个首屏。

## 2. 桌面端结构

顶部经营坞维持现有全局导航，高度和功能不变。首屏主体位于同一张连续画布中，采用约 45% / 55% 双栏：

- 左栏上部是紧凑标题区，包含经营日期、主标题和一句说明。
- 左栏下部是荧光绿链接利润焦点，展示链接、异常原因、SKU 数量、实际到手、暂算利润和“处理链接”动作。
- 右栏上部是深色七天信号仪表，成交均价折线、销量柱、同步状态和经营日期共用一个坐标区域。
- 右栏下部是三格经营判断：价格、动销、下一步动作。
- 七天信号底部保留四个核心指标：销量、GMV、实际到手、利润。

首屏目标是在 1280 × 720 视口中完整出现经营焦点、趋势主体和四个核心指标，不依赖首次滚动才能完成主要判断。

## 3. 排版与尺寸规则

- 首屏主体顶部与经营坞间距控制在 18–24px。
- 桌面端双栏间距控制在 16–20px，左右模块视觉顶线和底线对齐。
- 主标题使用两行以内，字号约 36–46px；禁止恢复到 60px 以上的海报式标题。
- 左侧利润焦点高度由内容决定，不通过大面积空白制造视觉冲击。
- 右侧趋势图表高度约 150–190px，足够识别趋势但不占据整屏。
- 日期筛选收进标题区或经营判断区，不再作为孤立控件漂浮在标题下方。
- 金额与销量继续使用等宽数字，标签、数值和单位基线对齐。

## 4. 视觉层级

仅保留三个主要层级：

1. 深墨色经营坞与七天信号仪表，负责系统框架和数据分析。
2. 荧光绿利润焦点，负责当天最重要链接和主动作。
3. 白色或浅灰连续画布，负责日期、解释和判断摘要。

不新增装饰卡片、悬浮小组件、无业务含义的光效或多余图标。圆角、阴影和细线只用于区分可交互区域和数据层级。

## 5. 数据与交互

- 所有值继续来自现有 `makeOverviewPulseModel` 和利润仓库，不写死展示数据。
- “处理链接”仍进入当前 JZZ 链接详情。
- 日期筛选继续控制总览日期范围，但收进统一排版，不改变其筛选逻辑。
- 未同步日期继续明确显示“待同步”，不补造七天趋势。
- 价格、动销、动作三格摘要由当前模型已有状态推导；若数据不足，使用可操作的等待条件。

## 6. 响应式

- 1180px 以下允许双栏比例调整为 42% / 58%，标题字号同步下降。
- 760px 以下改为单列：标题 → 利润焦点 → 七天趋势 → 四个指标 → 三格判断。
- 手机端顶部导航可横向滚动，但页面主体不得横向溢出。
- 手机端主标题保持两行以内，不出现孤字；利润金额保持同一行或两列对齐。

## 7. 代码边界

- 主要修改 `19-premium-shell-overview.css` 的首屏布局规则。
- 仅在必要时微调 `index.html` 的结构顺序；不把业务数据直接写进 HTML。
- 保持利润脉冲绘制函数只有一份实现。
- 不修改次级总览表格、利润详情计算、同步接口和数据库。
- 工作树包含其他未提交修改；实现时只处理本规格涉及文件，不提交或覆盖无关改动。

## 8. 验收标准

- 1280 × 720 首屏不滚动即可看见链接结论、实际到手、暂算利润、七天趋势和核心指标。
- 标题不再成为最大面积元素，利润焦点和趋势成为视觉中心。
- 左右栏顶线、底线、内部间距一致，没有悬空卡片或大块无意义留白。
- 320px 页面宽度等于视口宽度，无横向溢出。
- “处理链接”可用，日期筛选可用，浏览器无控制台错误。
- 完整项目检查、利润模型测试和正式构建通过。
