# 总览统一经营主图与首屏指挥面设计

## 目标

把总览首屏从“空态大卡片 + 两张并列趋势图”调整为一条明确的经营判断路径：先看到当前状态与优先动作，再用一张深绿色双线主图判断 GMV 与成交订单的共同变化，最后在同一屏内查看来源贡献和重点链接经营结果。

本次调整必须解决四个已确认问题：

1. 首屏视觉过于平淡，核心结论、关键数字和下一步动作没有形成明确焦点。
2. 多店 GMV 与重点链接价量各占一张大图，用户感知为重复，经营判断被拆散。
3. 当日尚未同步时，图表把缺失数据画成 0，容易制造 GMV 暴跌的错误判断。
4. 来源贡献、重点链接、利润和同步状态缺少统一排布，信息虽多但阅读顺序不清晰。

## 已确认的业务口径

- 双线主图的两个指标固定为“店群 GMV”和“店群成交订单数”。
- 两条线必须使用同一批店群日报、同一个滚动近 7 日范围，不允许把店群 GMV 与单条链接指标混在同一坐标系统。
- GMV 使用左侧金额轴，成交订单数使用右侧订单轴。
- 客单价只作为 `GMV ÷ 成交订单数` 的派生信息出现在悬浮提示和摘要标签中，不增加第三条线。
- 日期有日报记录但 GMV 或订单为 0 时，允许显示真实的 0。
- 日期没有任何范围内日报记录时，必须标记为“待同步”，折线在该日断开，不得用 0 补点。
- 店铺通常 16:00 更新，工作台计划 17:00 同步；当前日尚未同步属于正常状态，不应被渲染成经营异常。
- 重点链接继续使用自己的真实近 7 日周期；它与店群主图周期不同时必须分别标明。

## 信息架构

### 1. 一体化首屏指挥面

日期筛选、同步状态、经营结论、关键指标和优先动作收进同一个连续表面，不再用上下割裂的色块或大面积空白制造层级。

桌面端采用 12 列结构：

- 左侧 5 列：经营状态标签、主结论、判断说明和经营下钻路径。
- 中间 4 列：四个关键指标，使用紧凑 2×2 网格。
- 右侧 3 列：同步节奏、数据完整度和唯一优先动作。

首屏指挥面不设置为填满视口的固定高度，由内容自然撑开。桌面端目标高度控制在约 260—320px；空态不得比有数据状态更高。

### 2. 日期和数据状态

- 快捷日期和指定日期继续位于总览顶部，但与日期说明、同步状态处于同一控制行。
- 所选范围有数据时，四个关键指标严格使用所选范围口径。
- 所选单日没有数据时，主状态改为“今日待同步”或“所选日期待同步”，而不是“所选范围还没有经营数据”的大幅空态。
- 单日待同步时，指标区可以展示最近一个完整经营日，但必须在指标区顶部明确标注“最近完整日 YYYY-MM-DD”，每个数字不得暗示为今日数据。
- 如果整个仓库没有任何历史日报，则指标显示 `—`，并提供“填写日报”入口；不得虚构最近完整日。

### 3. 统一经营主图

首屏指挥面下方立即展示一张全宽深绿色图表，标题为“近 7 日 GMV 与成交订单”。

视觉与交互规则：

- 背景使用项目现有深墨绿色仪表盘色，不再保留蓝色 GMV 大图。
- GMV 使用高亮酸绿色实线和轻量渐变面积；成交订单使用更浅的薄荷绿色折线，可使用短虚线或不同节点形状增强辨识。
- 左轴显示紧凑金额，右轴显示订单数；两侧轴标签只保留必要刻度。
- 横轴固定显示 7 个自然日；待同步日显示弱化的日期和“待同步”状态，不落到零点。
- 最新有效日节点具有清晰光晕，但不使用持续动画。
- 悬浮提示按同一日显示：日期、GMV、成交订单、派生客单价和数据状态。
- 图表头部展示近 7 日 GMV 合计、订单合计、平均客单价和有效数据天数；这些是紧凑摘要，不再拆成第二行大型 KPI 卡。
- 当前 7 日不足 7 个有效数据日时显示“当前仅 N 天数据”，禁止生成误导性环比。

### 4. 图表下方经营证据带

主图下方使用一条紧凑证据带承接“为什么变化”和“下一步处理什么”。桌面端采用 `0.88fr / 1.12fr` 两列，不强制等高。

#### 左侧：来源贡献

- 保留联盟 GMV、商品卡、未归类成交和广告归因。
- 先显示一句变化结论，再用横向占比条和三项金额解释来源结构。
- 广告归因继续独立展示，不并入交易来源占比，防止重复计算。
- 不再保留单独的大型来源 Canvas；来源证据以紧凑结构呈现。

#### 右侧：重点链接决策卡

- 只保留一个重点链接，不再在总览中展示第二张大型趋势图。
- 卡片顶部显示产品、店铺、链接、SKU 数量和链接真实周期。
- 核心指标固定为：成交均价、销量、GMV、实际到手、暂算/最终利润。
- 卡片必须给出一句经营判断和一个主动作“处理此链接”。
- “成交均价”和“实际到手”继续分开；实际到手只扣运费和平台佣金，产品成本、样品和广告继续由利润模块单独核算。
- 更细的日趋势、SKU 明细和费用编辑继续在利润与成本模块完成，总览不重复实现。

## 数据模型与模块边界

新增可测试的纯函数 `makeOverviewOperatingTrendModel(entries, range)`，只负责把范围内店群日报转换为统一趋势模型：

```text
points[] = {
  dateKey,
  synced,
  gmv,
  orders,
  averageOrderValue
}

summary = {
  gmv,
  orders,
  averageOrderValue,
  syncedDays,
  expectedDays
}
```

规则：

- `synced` 以该日期是否存在范围内日报记录判断，不能以 GMV 是否大于 0 判断。
- `averageOrderValue` 仅在订单数大于 0 时计算，否则为 `null`。
- 汇总只累加已同步点；待同步点不参与合计和均值。
- 当前周期或前一周期数据不足时，继续使用现有完整性规则禁止环比。

新增纯函数 `latestCompleteOverviewDay(entries, selectedDate)`，仅用于“所选单日待同步”状态：

- 只向前查找，不得使用未来日期。
- 返回最近一个存在范围内日报记录的自然日及其汇总。
- 没有历史记录时返回空结果。

业务计算保留在总览模型模块，Canvas 只消费已形成的趋势模型；不得把同步判断、客单价计算或最近完整日查找堆进绘图函数。

## 视觉层级

- 全页仍以暖白和浅灰绿色为基础，深绿色只用于经营主图和关键动作，避免再次出现上下两个巨大色块。
- 首屏主结论字号明显高于指标和值，但空态标题不得大到占据半屏。
- 状态使用语义色：待同步为中性灰绿，稳定为绿色，重要风险为琥珀色，紧急风险为红色。
- 卡片边框、阴影和圆角沿用现有高级浅表面语言；减少装饰性网格和无功能的发光。
- 日期、周期、数据完整度和指标单位必须就近显示，不让用户依赖说明文字猜口径。
- 关键数字保持单行；长产品名、链接名和经营判断允许在完整词组边界换行，禁止孤字。

## 响应式

- `>= 1180px`：一体化首屏为 5/4/3 列；主图全宽；证据带为来源贡献和重点链接两列。
- `760—1179px`：首屏结论占整行，指标与动作在下一行；证据带改为单列。取消原有经营分析维度切换。
- `< 760px`：日期控件可换为两行但保持连续表面；指标使用两列；主图保持 7 日横轴并缩减刻度；来源和重点链接顺序堆叠。
- 约 `320px`：页面不得整体横向溢出；主动作满宽；指标、日期和长文案不得出现缺字、孤字或少字换行。

## 空态、异常态与交互

- 当日待同步：首屏显示最近完整日证据，主图显示滚动 7 日中的待同步断点。
- 整体无历史数据：首屏、主图和证据带使用同一个简洁空态，不重复出现三个“去填写日报”按钮。
- 重点链接无数据：重点链接卡显示同步节奏和进入利润模块的入口，但不占用大图高度。
- 来源数据缺失但 GMV/订单存在：主图正常绘制，来源贡献单独提示“来源待同步”。
- 图表在日期变化、数据更新、总览重新激活和容器尺寸变化时按当前可见尺寸重绘。
- “处理此链接”继续保留现有产品和链接 ID，并只执行一次导航。

## 验收标准

- 1440px 首屏无需滚动即可看到经营结论、核心指标和统一双线主图的主要部分。
- GMV 与成交订单使用相同日期和店群范围；双轴、图例和悬浮提示不会混淆单位。
- 2026-08-09 无日报时显示待同步断点，不出现从 8/8 正常值跌到 0 的误导折线。
- 单日待同步时，最近完整日数据具有明确日期标签；不会被误认为今日数据。
- 重点链接的成交均价、销量、GMV、实际到手和利润均可在主图下方看到，并能进入正确链接详情。
- 来源贡献与广告归因口径保持正确，不发生重复计算。
- 1179px、760px、390px 和 320px 均无整页横向溢出；图表和长文本保持可读。
- 今日、昨日、近 7 日、近 30 日和指定日期切换均不破坏布局、同步状态和数据口径。
- 总览、日报、任务、利润模块既有数据和入口保持可用。

## 非目标

- 不修改日报中心和任务中心的信息架构。
- 不修改利润核算公式、成本历史、SKU 动态模型或云端持久化结构。
- 不在总览中增加新的数据录入流程。
- 不用动画、装饰大屏或额外图表替代明确的经营结论。

## 已解决的歧义

- “成交”固定解释为成交订单数，不是销量或成交均价。
- 主图固定使用店群口径，不混入单条链接数据。
- 待同步与真实零成交是两种不同状态。
- 重点链接保留经营指标和处理入口，但不再保留第二张大型趋势图。
