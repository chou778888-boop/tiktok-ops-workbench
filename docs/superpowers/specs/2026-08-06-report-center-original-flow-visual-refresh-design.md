# 日报中心原流程视觉升级设计规格

## 目标

恢复日报中心改版前的纵向工作流和团队既有使用习惯，只提升页面设计质感，不改变日报字段、展开逻辑、数据汇总、任务同步、周报生成或记录查询逻辑。

本规格取代 `2026-08-06-report-entry-command-center-design.md` 中的 60/40 填写优先布局，但保留此前已经完成的岗位渐进展开能力。

## 页面结构

页面按团队日常阅读顺序恢复为四段：

1. 页面标题、查看日期与岗位提交进度。
2. “今日团队日报”和“自动团队摘要”并排展示；两块内容等高、信息密度稳定。
3. “今日行动重点”独立占据一整行，继续展示完成、异常、跟进与协作。
4. “提交岗位日报”独立占据一整行；基础字段位于顶部，选择岗位后，岗位工作导航、结果字段和经营闭环在同一卡片内向下展开。

自动周报与日报记录继续保持在上述主流程之后，结构与功能不变。

## 交互与业务边界

- 保留“先选择岗位，再显示详细字段”的渐进展开逻辑。
- 保留全部现有 DOM 容器 ID，避免影响日报渲染、编辑、保存、任务同步和周报计算。
- 不新增步骤、标签页、抽屉、悬浮侧栏或新的填写入口。
- 不改变岗位选项、字段顺序、默认值、校验规则、任务闭环规则和数据结构。
- 不将摘要或经营结果固定在岗位表单右侧；岗位展开后始终使用完整页面宽度。

## 视觉方向

- 延续工作台现有的深墨绿、白色与浅灰绿体系，单页只使用一个品牌强调色。
- 顶部汇总区使用清晰的主次对比：经营结果更强，自动摘要更安静，但不使用大面积渐变或发光效果。
- 卡片圆角、边框、阴影、内边距与标题层级统一；减少大块空白和无意义高度。
- 数字使用等宽数字；标题保持完整，正文自然换行；按钮和表格文字不出现孤字或截断。
- 岗位展开区通过分组标题、浅色分区和稳定间距建立层级，不改动内容顺序。
- 桌面端利用完整宽度提高填写效率；中屏与手机端自然切换为单列，不产生页面级横向滚动。

## 响应式规则

- 桌面端：顶部汇总保持双列，行动重点与岗位表单均为全宽。
- 中屏：顶部汇总可保持双列至空间不足，再切为单列。
- 手机端：所有主区块单列；岗位矩阵允许容器内部滚动，但页面本身不得横向溢出。
- 岗位展开前后，页面主结构和阅读顺序保持一致。

## 验收标准

1. 岗位展开后不再出现右侧超长空栏或大面积空白。
2. 岗位表单始终使用完整可用宽度。
3. 页面顺序恢复为“汇总 → 行动重点 → 岗位填写 → 周报 → 日报记录”。
4. 现有日报相关测试、项目检查与构建全部通过。
5. 390px、760px、1440px 三个宽度下无页面级横向溢出，文本完整可读。
6. 选择岗位、填写、保存、编辑日报、生成任务、自动汇总和周报均保持原有行为。

## 非目标

- 不重做日报数据模型。
- 不调整运营指标或字段定义。
- 不修改其他工作台页面。
- 不引入新的组件框架、动画系统或依赖。
