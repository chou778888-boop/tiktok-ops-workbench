# 日报中心填写优先工作台设计规格

## 目标

将日报中心从“汇总信息优先”调整为“每日填写优先”。运营人员进入页面后，应在首屏内完成岗位选择并开始填写，同时能看到当天岗位覆盖、经营结果和团队摘要，不需要先穿过大面积空汇总区。

## 使用场景

- 运营成员每天提交一个岗位结果，岗位人数不作为考核口径。
- 主管查看当天四个核心岗位是否覆盖、是否存在风险和需要协作的事项。
- 团队摘要、周报和历史记录均由现有数据自动生成，不新增数据口径。
- 复杂岗位字段仍采用现有渐进披露：先选择岗位，再展开岗位专属填写项。

## 信息架构

日报中心按以下阅读和任务顺序排列：

1. 页面标题、查看日期与岗位提交进度。
2. 首屏双栏工作台：左侧提交岗位日报，右侧经营结果与自动摘要。
3. 今日行动重点：完成、异常、跟进、协作四类信息，桌面端为 2×2，手机端单列。
4. 自动周报。
5. 日报历史记录。

## 首屏结构

### 页面标题

- 标题：`今天的岗位结果，直接在这里交付。`
- 辅助说明沿用“按岗位结果汇总，不绑定固定人数；异常与跟进同步任务中心”的业务事实。
- 查看日期和岗位覆盖进度与标题同层，避免被深色卡片包裹。

### 左侧主任务区

- 占桌面端约 60%。
- 使用明亮表单表面，保证长时间填写低疲劳。
- 首行展示“提交岗位日报”和已有说明。
- 日期、岗位、填写人、风险和状态保持现有字段与 ID，不改变提交逻辑。
- 选择岗位后，现有 `#reportDetails` 在原位置展开。

### 右侧经营上下文

- 占桌面端约 40%。
- 上部为深色经营结果仪表，承载现有 `#reportMetrics` 四项数据。
- 下部为自动团队摘要，承载现有 `#dailyDigest` 和复制按钮。
- 两部分的总高度与左侧初始表单接近，首屏形成完整工作区。

### 今日行动重点

- 保留现有 `#dailyManagementBoard` 数据渲染。
- 桌面端由四个横向长卡改为 2×2 紧凑矩阵，降低横向扫视成本。
- 空状态高度降低；有数据时列表仍可滚动。
- 完成、异常、跟进、协作继续使用语义色，但颜色只用于状态识别。

## 视觉语言

- 延续工作台的黑绿视觉系统：深墨色经营结果、酸绿色焦点和中性浅色表单。
- 表单控件、文字和边框保持克制，主要操作按钮使用深墨色。
- 卡片圆角为 12–16px，不增加装饰性玻璃效果、渐变文字或无意义动效。
- 表格数值上下左右居中，正文不截断重要信息。

## 响应式

- `> 1180px`：主任务区与经营上下文为 60/40 双栏，行动重点为 2×2。
- `761–1180px`：首屏改为单列，提交表单优先；经营结果与摘要随后展示。
- `<= 760px`：表单基础字段单列，行动重点单列，按钮触控高度至少 42px。
- 页面不得产生横向滚动；中文标题按语义短句换行，不出现孤字。

## 技术边界

- 不更改日报数据模型、保存流程、任务同步、自动周报或 AI 分析逻辑。
- 不删除或修改现有关键 ID。
- 新增独立 CSS 模块 `20-report-command-center.css`，置于总览模块之后，集中管理日报中心的新结构和响应式覆盖。
- 新增结构契约测试，验证首屏语义容器、DOM 顺序、样式模块注册与关键响应式规则。

## 验收标准

- 桌面 1440px 首屏能同时看到完整基础表单、四项经营结果和自动摘要入口。
- “提交岗位日报”在 DOM 和视觉顺序上先于经营汇总和行动重点。
- 手机 390px 无横向溢出，岗位选择与基础字段不被截断。
- 现有日报渐进披露、保存和任务同步测试全部通过。
- 完整项目检查和生产构建通过。
