# 链接利润真实单日验证设计

## 目标

用 2026-08-03 已核对的 TikTok Shop 数据替换利润工作台演示数据，验证“产品整体 → 单条链接 → SKU”的真实使用链路。保留现有双栏布局与最近 7 天框架，不制造未取得的数据。

## 数据边界

- 店铺：Ufist-DreamWeave。
- 产品：JZZ，统一产品成本 $12/件。
- 链接：`1731776510060368401`，当天 Product Analytics GMV $675.52、37 单、39 件。
- Earnings Analytics：平台确认销售额 $697.60、平台订单成本 $66.13、实际到手 $631.47。
- 经营与财务口径差异：$697.60 - $675.52 = +$22.08，单独展示且不重复参与扣减。
- 产品成本：39 × $12 = $468.00。
- 广告、样品与人工调整尚未取得，保持待补状态；成本后暂算利润为 $631.47 - $468.00 = $163.47。

## 展示口径

链接层采用完整利润桥：经营 GMV → 平台确认销售额 → 口径差异 → 平台订单成本 → 实际到手 → 产品成本 → 待补内部费用 → 暂算利润。平台优惠已包含在平台确认销售额中，只做说明，不重复扣除。

SKU 层仅展示售价、销量、GMV、产品成本与商品毛利。平台费用属于链接结算口径，在没有可靠的 SKU 归因数据时不得按比例伪分摊。

最近 7 天仍保留完整日期窗口；只有 8 月 3 日显示真实值，其余日期显示待同步/暂无数据，不补造趋势。

## 状态与录入

- 来源标签改为真实店铺样本并显示数据更新时间。
- 广告、样品、调整未填时输入框为空，不默认为 0。
- 内部费用未完整时，利润状态为 `provisional`，页面统一使用“暂算利润”和“待补”措辞。
- 团队完成全部内部费用后，才可显示最终利润。

## 可维护性

真实样本仍通过现有 repository/domain/selector/view 分层进入页面。财务字段使用明确命名，不把平台优惠、平台订单成本和经营 GMV混在一个抽象“佣金率”里；后续新增店铺、链接和日期无需修改页面结构。
