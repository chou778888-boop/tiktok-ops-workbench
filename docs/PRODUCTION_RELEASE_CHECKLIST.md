# 生产发布与数据回滚清单

本清单用于把本地统一版本发布到 Cloudflare Pages。代码发布和业务数据迁移必须分开执行；默认只发布代码，不写入或清理 D1 业务数据。

## 发布前

先运行 `npm run predeploy:check`。该命令会执行完整测试与构建、编译 Pages Functions、读取生产只读摘要，并在以下任一条件存在时阻止部署：工作区未形成可追溯版本、preview 与 production 共用 D1、生产数据快照不可用、或未确认初始密码已轮换。

正常发布应在同一终端设置 `TK_PRODUCTION_PASSWORDS_ROTATED=1`。如果负责人明确决定暂不轮换，可仅针对本次命令设置 `TK_ACCEPT_INITIAL_PASSWORD_RISK=1`；门禁会放行但持续输出风险警告。不得把这两个变量写入仓库、`.env` 或长期系统配置。

1. 记录当前生产 Pages release、Git commit、D1 数据库名称和状态 revision。
2. 对生产 D1 创建可恢复备份，并核对备份时间、文件大小和恢复命令；未验证备份时不得执行数据迁移。
3. 确认所有初始化账号已完成密码轮换；仍使用账号名作为初始密码时禁止发布到公网。
4. 确认 preview 环境使用独立 D1；如果 preview 与 production 指向同一数据库，只允许本地 `--persist-to` 验证，禁止远程预览写入。
5. 运行 `npm run check` 和 `npm run build`，确认生成单一 boot 脚本与单一 workbench 脚本。
6. 编译 Pages Functions，并核对 D1 `DB` 与 AI binding 在生产环境存在。
7. 在本地预览逐项检查总览、日报、任务、利润、达人、学院、登录、筛选、编辑、展开、空状态、长文字和窄屏。
8. 确认本次没有初始化、覆盖、删除或批量改写 `reports`、`tasks`、`profit*` 等团队状态集合。

密码轮换由管理员核对生产账号后，在执行部署的同一终端设置 `TK_PRODUCTION_PASSWORDS_ROTATED=1`。该变量只表示本次人工核对已完成，不包含密码内容；禁止把密码或 Cloudflare Token 写入仓库。

## 发布顺序

1. 先发布 Pages 代码，不运行 D1 migration，不导入本地状态。
2. 在正式域名只读核对 release、登录、`/api/bootstrap` revision 和各集合数量。
3. 检查历史重复任务是否仅被折叠展示；展开后原始记录数量和作废审计信息必须完整。
4. 检查周报默认窗口为截至昨日的 7 个完整自然日；上周期不完整时必须显示“上周期数据不完整”，且 AI 分析不得收到残缺对比数据。
5. 用户确认主要链路后，才允许单独评估数据迁移。

## 数据迁移原则

- 优先使用可重复执行、只新增缺失字段的迁移，不使用整份状态覆盖。
- 任务重复记录不做物理删除；如后续确需清理，先生成包含 ID、来源、状态、审计记录和保留主记录的预览清单。
- 利润产品、链接、SKU 和历史日数据按稳定 ID 合并；无法唯一匹配的记录进入人工确认清单。
- 迁移前后分别记录集合数量、关键 ID 样本和 revision，任何异常立即停止后续写入。

## 回滚

1. 页面异常：回滚到发布前 Pages release；不要同时恢复 D1。
2. 数据异常：停止所有写入，先比较迁移前后 revision 和差异清单，再由用户确认恢复时间点。
3. 只有确认需要恢复数据时，才从已验证备份恢复 D1；恢复后重新核对登录、日报、任务、利润及 revision。
