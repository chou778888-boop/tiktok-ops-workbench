# 安全基线与后续计划

## 已在本地代码完成

- 静态页面增加 CSP、禁止嵌入、权限策略和 MIME 嗅探保护。
- 页面脚本全部外置，为严格脚本策略提供基础。
- API 统一增加安全响应头。
- 写接口拒绝跨站请求，并限制超大请求体。
- AI 分析继续保留输入上限、缓存和小时级限流。
- 状态写入继续使用 revision 和日报 guard，避免旧页面覆盖新内容。

## 当前身份认证

- 未登录用户不能进入工作台或读取团队状态。
- 每位成员使用独立账号，服务端验证密码哈希并签发 HttpOnly 会话 Cookie。
- 浏览器前端不保存明文密码；“记住账号”优先调用浏览器密码管理器。
- 团队任务对成员可见，管理员保留完整后端权限边界。
- 账号停用后，bootstrap 会拒绝对应会话。
- 初始化迁移中的账号名密码只用于首次受控建库；正式域名开放前必须逐账号轮换，未轮换时视为发布阻断项。

后续如接入自有域名，可在现有账号系统外再增加 Cloudflare Access 作为第二层访问控制，但不能替代工作台内部人员身份。

## 仍需持续执行

### 1. 数据恢复

- 发布结构变更前记录 D1 Time Travel bookmark。
- 每月额外导出一份长期归档，避免只依赖有限恢复窗口。
- 恢复生产数据属于破坏性操作，必须先确认时间点和影响范围。

### 2. 审计与权限分级

后续数据表应记录：操作者、动作、记录类型、记录 ID、时间、变更前后摘要。至少区分普通成员、负责人和管理员。

### 3. 数据结构演进

目前团队主状态仍集中保存在单条 JSON 中。短期有 revision 冲突保护，长期应把日报、任务、达人、成本档案拆成独立表，并保留外键和审计记录。

## 发布安全检查

- `pnpm check` 和 `pnpm build` 均通过。
- 本地无控制台错误。
- 不包含密钥、真实密码或未脱敏截图。
- 初始化账号已完成密码轮换，迁移文件不会在代码发布时重复执行。
- preview 与 production 数据绑定已隔离，或明确禁止远程 preview 写入。
- 本次 migration 可回滚。
- 云端数据未被本地预览覆盖。
- 用户确认后才部署。
- 重构、构建和部署不执行 D1 migration、状态初始化或业务数据导入。
- 远程数据写入必须来自单独、明确的业务操作请求，不能附带在代码发布流程中。
